# Intecre.Utilities

A library of utility functions and classes for Beckhoff TwinCAT 3, built and tested on TwinCAT 3.1.4026.

The user guide, with a quick start, examples, defaults, fixed limits and what each log message means: [intecre.github.io/twincat-utils/user-guide.html](https://intecre.github.io/twincat-utils/user-guide.html). Its source is [docs/user-guide.html](docs/user-guide.html), which also opens in a browser straight from a clone.

## What is in it

- **String functions**: `F_Concat3` to `F_Concat7` for `T_MaxString`, and the `_Large` family plus `F_ConcatLarge` / `F_ClearLarge` for `LongString` (`STRING(300)`, length set by `StringsParams.MAX_STRING_LENGTH`).
- **TryParse functions**: `TryStringToDint`, `TryStringToUdint`, `TryStringToWord`, `TryStringToLreal`. They mimic C# `TryParse`: `TRUE` on success, the value through `VAR_IN_OUT`, `0` when parsing fails.
- **Collections**: `FB_StringList`, `FB_LongStringList`, `FB_UdintList`, `FB_PointerList`, `FB_TargList` and `FB_Dictionary` (string key to `T_Arg`), all fixed at `GVL_List.LIST_SIZE` entries, plus `F_DictionaryValuesCrc`.
- **Logging**: `F_LogDebug` / `F_LogInfo` / `F_LogWarning` / `F_LogError` write to the TwinCAT log filtered by `LogConfig.LogLevel`, and forward to any `I_ExternalLogger` set in `LogConfig.ExternalLogger`. `FB_LogOnEdge` and the typed edge blocks log once per edge.
- **Task information**: `T_Task` wraps `_TaskInfo` (cycle time, cycle count, distributed clock, date and time strings); `T_Timer` is a DC-clock based timer with on, off and pulse-train outputs.
- **ADS helpers**: `T_GetHandle`, `T_ReleaseHandle`, `T_AdsReadWrite`, `T_AdsWrite`, `T_CallMethod` and `T_InvokeRpcMethod` (call a `{attribute 'TcRpcEnable'}` method by symbol name).
- **Control**: `FB_P_Control`, `FB_I_Controller`, `FB_PI_Controller` and `FB_AlphaBetaFilter`.
- **Base classes**: `T_NamedBase` (instance and object names from the instance path, with logging methods), `FB_Assert` and `T_TestBase` from before TcUnit.
- **Terminal interfaces**: process-image structures for EL3xxx / KL3xxx analogue inputs, EL9xxx system terminals and the EtherCAT standard diagnostics, plus OPC UA point structures.
- **Diagnostics**: `T_MdpReadCpuTemp` (needs Tc3_IPCDiag, from 4.2.0.0; Tc2_MDP before. **Needs retesting on a Beckhoff IPC**: since the move to Tc3_IPCDiag it has only been compiled, and no test covers it) and `T_WritePersistentData`.

## Getting it

Three ways, newest first:

1. **TcPkg package** `Intecre.Utilities` from the Intecre TcPkg feed. The package installs the library into the TwinCAT library repository and declares the Beckhoff library packages it needs, so `tcpkg install Intecre.Utilities` brings everything. The packed `.nupkg` is also committed under `dist/`.
2. **The `.library` file** `IntecreUtilities.library` in the repository root: install it with the Library Repository dialog in the XAE or with `RepTool`.
3. **The source**: open `IntecreUtilities/IntecreUtilities.sln` and save the `IntecreUtilities` PLC project as a library, or include the sources in your own project.

Reference it as the placeholder `Intecre.Utilities` (namespace `Intecre_Utilities`).

## Building and testing

The solution holds two PLC projects:

- `IntecreUtilities`: the library.
- `TestRunner`: the TcUnit suites, one `*_Tests` function block per library object under `Tests/`, with test doubles under `Mocks/`. `MAIN` declares every suite and calls `TcUnit.RUN_IN_SEQUENCE()`.

`TestRunner` has two tasks. `PlcTask` (10 ms) runs `MAIN`. `SlowTask` (50 ms) runs `ControllersInSlowTask`, so the controller suites can check that a controller uses the cycle time of the task that calls it.

`TestRunner` references the library through the placeholder, so the library must be installed in the repository before the tests build. The loop while developing is:

1. Change the library, then *Save as library and install* (or `tclib publish`).
2. Build `TestRunner` and activate the configuration on a runtime. The TwinCAT usermode runtime (`TC170x.UsermodeRuntime.XAR`) on the engineering PC is enough; the ADS tests talk to the test PLC's own port (851).
3. Read the results in the error list or in `C:\TcUnit_xUnit_testresults.xml` (xUnit publishing is switched on in the `TcUnit` reference parameters).

Current state: 32 suites, 171 tests, all passing on 4026.25 with the usermode runtime. The two ADS suites need a running router and fail on a target without one.

## Releasing

Versions follow `major.minor.build.revision` in the `.plcproj`; `Global_Version` and `F_GetVersion` are generated from it. Publishing uses [Intecre TwinCAT Library Tools](https://github.com/Intecre) (`tclib`), configured in `IntecreUtilities.libtools.json`: it compiles, saves `IntecreUtilities.library` to the repository root, installs it, packs the TcPkg package into `dist/`, pushes it to the `Intecre` TcPkg source and tags the commit `v<version>`.

```bash
tclib publish --project IntecreUtilities/IntecreUtilities/IntecreUtilities/IntecreUtilities.plcproj
```

Release notes are kept in the library description (Project Information in the XAE, or `tclib props`).
