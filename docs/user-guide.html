Utilities user guide

The everyday building blocks of an Intecre PLC project, in one TwinCAT 3 library: logging, fixed-size lists and a dictionary, long strings, safe parsing, task information, a timer, ADS calls by name and PI control. This guide shows how to use each part, and the defaults and limits to know first.

1What the library does

The library is Intecre.Utilities. Reference it as the placeholder Intecre.Utilities. Its namespace is Intecre_Utilities.

PartWhat it gives you
LoggingF_LogInfo and its siblings write to the TwinCAT log, filtered by one level, and can copy every message to a logger of your own.
Named objectsT_NamedBase gives a function block its instance path, and logging methods that put the path in front of each message.
Lists and dictionaryFixed-size lists of strings, numbers, pointers and T_Arg, and a dictionary from text keys to your variables.
Strings and textJoining up to seven strings, strings longer than 255 characters, parsing text into numbers without surprises, and reading or writing a variable as text.
Task information and timerT_Task reads the cycle time, cycle count and clock of a PLC task. T_Timer times from the distributed clock and needs no cyclic call.
ADSCalls a method on any PLC by name, and reads and writes over ADS, spread over several cycles.
Controllers and filterP, I and PI controllers, and an alpha-beta filter.
I/O and OPC UA structuresProcess-image structures for common analogue and system terminals, EtherCAT diagnostics and the OPC UA client device.
DiagnosticsThe IPC's CPU temperature, and writing persistent data at a fixed period.

2Quick start

You need TwinCAT 3.1 build 4026 or later. The library, and the Beckhoff libraries it uses, come as TcPkg packages.

  1. Add the Intecre feed. You do this once per PC. The feed is private, so first make an access token: sign in at dev.azure.com/intecre, open User settings > Personal access tokens, and create a token with the Packaging (Read) scope. Then, in PowerShell run as Administrator: 
    tcpkg source add -n Intecre `
  -s https://pkgs.dev.azure.com/intecre/Intecre-Packages/_packaging/tcpkg/nuget/v3/index.json `
  -u your.name@yourcompany.com
    When it asks for a password, paste the token.
  2. Install the library. Close TwinCAT XAE, then run: 
    tcpkg install Intecre.Utilities
    This puts the library in the TwinCAT library repository, with the Beckhoff libraries it uses. Later, tcpkg upgrade Intecre.Utilities brings a new version.
  3. Reference it. In your PLC project, right-click References, choose Add library, and pick Intecre Ltd > Intecre.Utilities. Its names then resolve without a prefix. If one clashes with a name in your project, qualify it with the namespace, for example Intecre_Utilities.T_Timer.
  4. Turn the log on. Set the level once at start-up: 
    LogConfig.LogLevel := E_LogSeverity.Info;
    The log is off by default. Without this line, nothing from the library or from your own F_Log... calls reaches the TwinCAT log.
  5. Try it. Give a function block a name and a message: 
    FUNCTION_BLOCK T_Conveyor EXTENDS T_NamedBase

METHOD Start
LogInfo('Started');
    PROGRAM MAIN
VAR
  infeedConveyor : T_Conveyor;
  startRequested : BOOL := TRUE;
END_VAR

LogConfig.LogLevel := E_LogSeverity.Info;

IF F_Gate(startRequested) THEN
  infeedConveyor.Start();
END_IF
    Build, activate and run. The Error List shows the message once, under Messages: 
    'PlcTask' (350): MAIN.infeedConveyor: Started
Without TcPkg Download IntecreUtilities.library from the latest GitHub release and install it with PLC > Library Repository > Install. Then install the Beckhoff libraries it uses yourself: Tc2_Math, Tc2_Standard, Tc2_System, Tc2_Utilities, Tc3_IPCDiag and Tc3_Module.

3Logging

Turning it on

Set the level once at start-up. Messages at that severity and above are logged.

LogConfig.LogLevel := E_LogSeverity.Info;
LevelLogs
DebugDebug, Info, Warning, Error
InfoInfo, Warning, Error
WarningWarning, Error
ErrorError
NoneNothing. This is the default.
Logging is off until you turn it on LogConfig.LogLevel starts at E_LogSeverity.None. Until you set a level, the library's own warnings are silent too, so a refused AddItem or a busy ADS block gives no sign.

Writing messages

F_LogInfo('Conveyor started');
F_LogWarning(F_Concat3('Low pressure on ', lineName, ''));
F_LogError('Door opened while running');
F_LogDebug('Entering homing');

Each message goes to the TwinCAT log, which XAE shows in the Error List. F_LogDebug puts DEBUG in front of its message. Each function returns the message when it was logged, and an empty string when the level filtered it out.

F_Logger(LogSeverity, Message) does the same with the severity as a parameter.

Logging once per edge

The edge blocks log when their Event input changes, not on every cycle while it stays set. Q is TRUE on the cycle the message was logged.

VAR
  doorOpenedLog : FB_LogWarningEdge;
  doorClosedLog : FB_LogInfoEdge;
END_VAR

doorOpenedLog(Event := doorOpen, Message := 'Door opened');
doorClosedLog(Event := doorOpen, Message := 'Door closed', EventFallingEdge := TRUE);

FB_LogInfoEdge, FB_LogWarningEdge and FB_LogErrorEdge each log at their own severity. FB_LogOnEdge takes the severity as an input and accepts Info, Warning or Error. Given Debug, it logs an error saying the severity is wrong, with your message attached.

Sending messages somewhere else as well

To copy every logged message to your own destination, such as a file, an HMI alarm list or a database, write a function block that implements I_ExternalLogger, and hand an instance to LogConfig.ExternalLogger.

FUNCTION_BLOCK T_HmiMessageLog IMPLEMENTS I_ExternalLogger
VAR
  lastMessage : T_MaxString;
  lastSeverity : E_LogSeverity;
END_VAR

METHOD AddToLog
VAR_IN_OUT
  Message : T_MaxString;
END_VAR
VAR_INPUT
  LogSeverity : E_LogSeverity;
END_VAR

lastMessage := Message;
lastSeverity := LogSeverity;
PROGRAM MAIN
VAR
  hmiMessageLog : T_HmiMessageLog;
END_VAR

LogConfig.ExternalLogger := hmiMessageLog;
LogConfig.LogLevel := E_LogSeverity.Warning;

The external logger receives only the messages that pass the level. Declare its instance somewhere that lives as long as the PLC runs, such as a program or a global variable list. To stop forwarding, set LogConfig.ExternalLogger := 0.

5Lists

BlockHolds
FB_StringListT_MaxString, up to 255 characters
FB_LongStringListLongString, up to 299 characters
FB_UdintListUDINT
FB_PointerListPVOID
FB_TargListT_Arg

All lists work the same way:

  • Each holds up to 100 items (GVL_List.LIST_SIZE). AddItem returns FALSE once the list is full.
  • Lists accept duplicates.
  • Indexes start at 0. FindIndex returns -1 when the item is not there.
  • RemoveIndex moves the later items down one place.
  • GetIndex past the end returns an empty string, 0 or a null pointer, so prefer TryGetIndex when the index may be out of range.
VAR
  activeAlarms : FB_StringList;
  alarmIndex : INT;
END_VAR

IF NOT activeAlarms.Contains('Door open') THEN
  activeAlarms.AddItem('Door open');
END_IF

alarmIndex := activeAlarms.FindIndex('Door open');
IF alarmIndex >= 0 THEN
  activeAlarms.RemoveIndex(TO_UDINT(alarmIndex));
END_IF

Going through every item

Let TryGetIndex end the loop:

VAR
  index : UDINT;
  alarm : T_MaxString;
END_VAR

index := 0;
WHILE activeAlarms.TryGetIndex(index, alarm) DO
  F_LogWarning(alarm);
  index := index + 1;
END_WHILE
Don't loop with FOR to Count - 1 Count is unsigned. On an empty list, Count - 1 wraps to the largest UDINT and the loop runs away.

What else the lists have

  • ContainsPartial and FindIndexPartialKey on the string lists match any item containing the given text.
  • CopyList and CopyListAndClear on the string lists copy every item into an ARRAY[0..GVL_List.LIST_SIZE - 1] of the list's item type.
  • GetAndRemoveIndex on FB_StringList returns an item and removes it in one call.
  • FB_TargList.Contains and FindIndex compare the data each T_Arg points at, so two arguments for different variables holding the same value match.

6Dictionary

FB_Dictionary maps a text key to a T_Arg, which points at one of your variables. Use it to reach variables by name, for example settings that an HMI or a recipe file sends as text.

VAR
  settings : FB_Dictionary;
  conveyorSpeed : LREAL := 1.5;
  operatingMode : INT := 2;
  setting : T_Arg;
  settingText : T_MaxString;
END_VAR

settings.AddItem('speed', F_LREAL(conveyorSpeed));
settings.AddItem('mode', F_INT(operatingMode));

IF settings.TryGet('speed', setting) THEN
  settingText := F_TargToString(setting);
  F_StringToTarg('2.0', setting);
END_IF

After this, settingText is '1.5' and conveyorSpeed is 2.0.

The dictionary stores where the variable is, not a copy of its value Reading through the dictionary always gives the variable's current value, and writing through it changes the variable. Only add variables that live as long as the dictionary: never a function's local variable or a VAR_TEMP.

AddItem returns FALSE, adds nothing and logs a warning (section 16) when:

  • the key is empty;
  • the value is empty, a T_Arg with no length;
  • the key is already there;
  • the dictionary already holds 100 entries.
MethodDoes
Contains(key)TRUE when the key is present
TryGet(key, value)TRUE, and the value, when the key is present
Get(key)The value, or an empty T_Arg
TryGetPartialKey(partialKey, value)The value of the first key containing the text
TryGetIndex(index, key, value)The key and value at a position, in the order they were added
Remove(key)TRUE when the key was there and is now gone
Clear()Empties the dictionary
CountThe number of entries

Noticing when any value changes

F_DictionaryValuesCrc returns a CRC-16 of every value in the dictionary, in the order they were added, and 0 for an empty dictionary. Compare it with the last one to see whether anything changed, for example before saving settings.

settingsChecksum := F_DictionaryValuesCrc(settings);
IF settingsChecksum <> savedSettingsChecksum THEN
  SaveSettings();
  savedSettingsChecksum := settingsChecksum;
END_IF

7Strings and text

Joining up to seven strings

statusText := F_Concat4('Axis ', axisName, ' at ', TO_STRING(position));

F_Concat3 to F_Concat7 return a T_MaxString. Anything past 255 characters is cut off. Empty parts add nothing.

Strings longer than 255 characters

LongString holds up to 299 characters. Join LongString variables with F_ConcatLarge for two, or F_Concat3_Large to F_Concat7_Large for more.

VAR
  reportHeader, reportBody, reportFooter, report : LongString;
END_VAR

report := F_Concat3_Large(reportHeader, reportBody, reportFooter);

When the parts add up to more than 299 characters, the earlier parts are shortened so that the last part is kept whole. F_ClearLarge(report) empties a LongString and zeroes its whole buffer.

Measuring a long string The standard LEN stops counting at 255 characters. Measure a LongString with LEN2(ADR(report)) from Tc2_Utilities.

Parsing text into numbers

The TryStringTo... functions return TRUE when the whole text is a valid number for the type, and write the number into the variable you pass. When they return FALSE, the variable is set to 0.

IF TryStringToDint(setpointText, setpoint) THEN
  F_LogInfo('Setpoint accepted');
ELSE
  F_LogWarning(F_Concat3('Not a whole number: ', setpointText, ''));
END_IF
FunctionAcceptsRejects
TryStringToDintDigits, with an optional leading minus: 123, -45+1, 1-2, letters, spaces, empty text
TryStringToUdintDigits up to 4294967295Any sign, spaces, empty text
TryStringToWordDigits up to 6553565536 and above, letters, empty text
TryStringToLrealDigits with an optional point and leading minus: 3.25, -0.5, 42Exponents such as 1e5, letters, empty text

CharIsNumber, CharIsNumberOrMinus and CharIsNumberOrPeriod test a single character, given as its byte value.

Reading and writing a variable as text

T_Arg comes from Tc2_Utilities. It records where a variable is, its type and its size. Make one with the Tc2_Utilities functions such as F_INT(variable), F_LREAL(variable) or F_STRING(variable).

F_TargToString(arg) returns the variable's value as text. F_StringToTarg(text, arg) converts text and writes it into the variable.

Both handle BOOL, BYTE, WORD, DWORD, USINT, SINT, UINT, INT, UDINT, DINT, REAL, LREAL and STRING. For any other type they log a warning: F_TargToString returns an empty string, and F_StringToTarg leaves the variable unchanged.

9Timer

T_Timer times from the distributed clock. It has no inputs and needs no cyclic call: set its properties, and read its outputs whenever you like.

VAR
  doorOpenTimer : T_Timer;
END_VAR

doorOpenTimer.SetPeriod := T#5S;
doorOpenTimer.Signal := doorOpen;

doorAlarm := doorOpenTimer.Q_On;
doorBeacon := doorOpenTimer.Q_PulseTrain;
PropertyMeaning
SignalThe input. Timing restarts whenever it changes. Writing the same value every cycle does not restart it.
SetPeriodThe period. Anything under 1 ms is stored as 1 ms.
Q_OnTRUE once Signal has been on for longer than the period
Q_OffTRUE once Signal has been off for longer than the period, after having been on at least once
Q_PulseTrainWhile Signal is on: low for the first half of each period, high for the second half
ElapsedTime, ElapsedTimeInMsThe time since Signal came on, and 0 while it is off

10ADS

The ADS blocks run a request over several cycles. Each one:

  • starts with a Try... method, which returns FALSE and logs a warning if a request is already busy;
  • must be called every cycle, as myBlock();, while the request runs;
  • reports through Busy, Done and Error, which it also offers as the I_TaskState interface.

Addresses use ST_AmsAddr. Leave its netId all zero for the local system, and set port to the target, for example 851 for the first PLC.

Calling a method on a PLC by name

T_InvokeRpcMethod calls a method marked {attribute 'TcRpcEnable'} on any PLC it can reach over ADS. In one request, it gets a handle for the method, calls it and releases the handle.

On the target PLC

FUNCTION_BLOCK T_Calculator

{attribute 'TcRpcEnable'}
METHOD AddNumbers : DINT
VAR_INPUT
  a : DINT;
  b : DINT;
END_VAR

AddNumbers := a + b;

On the calling PLC: the method's inputs, in order

TYPE ST_AddNumbersInputs :
STRUCT
  a : DINT;
  b : DINT;
END_STRUCT
END_TYPE

On the calling PLC: the call

VAR
  addNumbers : T_InvokeRpcMethod;
  addNumbersCall : ST_SymbolHandle;
  inputs : ST_AddNumbersInputs;
  sum : DINT;
END_VAR

addNumbers();

IF startCalculation THEN
  inputs.a := 20;
  inputs.b := 22;
  addNumbersCall.SymbolAddress.SymbolName := 'MAIN.calculator#AddNumbers';
  addNumbersCall.SymbolAddress.Ads.port := 851;
  addNumbersCall.SymbolAddress.WriteRef := F_BIGTYPE(pData := ADR(inputs), cbLen := SIZEOF(inputs));
  addNumbersCall.SymbolAddress.ReadRef := F_BIGTYPE(pData := ADR(sum), cbLen := SIZEOF(sum));
  addNumbers.TryInvokeMethodCall(symbolHandle := addNumbersCall);
  startCalculation := FALSE;
END_IF

calculationBusy := addNumbers.Busy;
calculationDone := addNumbers.Done;
calculationFailed := addNumbers.Error;

The symbol name is the instance path of the target function block, then #, then the method name. WriteRef points at the method's inputs, and ReadRef at where to put its return value. sum holds 42 once Done is set.

Point WriteRef and ReadRef at variables that outlive the request The block reads and writes them over several cycles. Never use the locals of a method or function.

Working with a handle yourself

To keep a handle and use it more than once, take the steps T_InvokeRpcMethod takes for you:

  1. T_GetHandle.TryGetHandle(symbolHandle := handle) fills in handle.Handle for handle.SymbolAddress.SymbolName.
  2. T_CallMethod.TryMethodCall(symbolHandle := handle) writes WriteRef and reads ReadRef through the handle.
  3. T_ReleaseHandle.TryReleaseHandle(symbolHandle := handle) frees it.

Raw read and write

T_AdsReadWrite.TryRequest(readWriteOptions) and T_AdsWrite.TryRequest(readWriteOptions) send one ADS read-write or write, to the index group and offset in ST_AdsReadWriteOptions. WriteParams and ReadParams are T_Arg values saying what to send and where to put the reply. The default timeout is 5 seconds.

11Controllers and filter

P, I and PI

VAR
  temperatureLoop : FB_PI_Controller;
END_VAR

temperatureLoop(
  ProcessVariable := measuredTemperature,
  Setpoint := targetTemperature,
  Kp := 2.0,
  IntegralConstant := 6.0,
  MaxLoopOutput := 100.0,
  MinLoopOutput := 0.0,
  Bias := 0.0
);
heaterPower := temperatureLoop.Output;
BlockWhat it does
FB_P_ControlTerm is Kp × (Setpoint − ProcessVariable).
FB_I_ControllerEach call adds Ki × error × cycle time of the calling task to Term, held between MinIntegralComponent and MaxIntegralComponent (±1000 by default). Pause holds the term, Reset restarts it from zero, and a Ki of 0 or less gives a term of 0.
FB_PI_ControllerOutput is the P term plus the I term plus Bias, held between MinLoopOutput and MaxLoopOutput. IntegralConstant is in repeats per minute, or per second when RepeatsPerMinute is FALSE. Integration pauses while the output is held at a limit and the error would push it further.
Set both output limits on FB_PI_Controller MaxLoopOutput and MinLoopOutput default to 0, which holds the output at 0 whatever the error.
Call each controller exactly once per cycle The I term integrates once per call, using the cycle time of the task that calls it. A second call in the same cycle integrates twice.
Versions before 4.1.0.0 used the cycle time of the first PLC task Whatever task called the controller, it integrated with the first task's cycle time, so a controller in a faster or slower task integrated too slowly or too fast. From 4.1.0.0, each controller uses its own task. Check the tuning of any loop that runs outside the first task (section 15).

Alpha-beta filter

FB_AlphaBetaFilter smooths a measurement and tracks its rate of change.

pressureFilter(
  measurement := rawPressure,
  deltaInSecond := task.CycleTimeInSecs,
  alpha := 0.3,
  beta := 0.01
);
smoothedPressure := pressureFilter.output;

alpha runs from 0 to 1: 1 passes the measurement straight through, and smaller values smooth more. Keep beta small, between 0.001 and 0.1. With a deltaInSecond of 0, the rate term is left out.

13Diagnostics

CPU temperature

T_MdpReadCpuTemp reads the IPC's CPU temperature through Beckhoff's Tc3_IPCDiag library every 500 ms. Call it every cycle and read CpuTemp, in degrees Celsius.

VAR
  cpuTemperature : T_MdpReadCpuTemp;
  cpuHotLog : FB_LogWarningEdge;
END_VAR

cpuTemperature();
cpuHotLog(Event := cpuTemperature.CpuTemp > 80, Message := 'CPU above 80 degrees');

SetUpdateTimerValue(T#2S) changes how often it reads. Busy, Error and ErrorId report the read in progress. ErrorId is the HRESULT that Tc3_IPCDiag returns, 0 when the last read worked. The library needs Tc3_IPCDiag, which comes from Beckhoff's stable TcPkg feed with the package.

Not yet checked on a Beckhoff IPC since 4.2.0.0 The move to Tc3_IPCDiag has only been compiled. No test covers it, because the user-mode runtime has no IPC diagnostics to read. Before you rely on CpuTemp, check on the target IPC that Error stays FALSE and CpuTemp matches the temperature the IPC's device manager shows.

Writing persistent data regularly

T_WritePersistentData writes the persistent variables of a PLC at a fixed period, so a power cut loses at most one period of changes. By default it writes on ADS port 851 every 10 seconds. Call it every cycle.

VAR
  persistentWriter : T_WritePersistentData;
  persistentWriterConfigured : BOOL;
END_VAR

IF NOT persistentWriterConfigured THEN
  persistentWriterConfigured := persistentWriter.SetConfig(WritePeriod := T#1M, AdsPort := 852);
END_IF
persistentWriter();

SetConfig returns TRUE when it takes the new period and port. A zero period or port 0 is rejected: it returns FALSE, and the current settings stay. WritePeriod and AdsPort read the settings back.

Set the port of the PLC you are in The default, 851, is the first PLC. A second PLC on port 852 that keeps the default writes the first PLC's persistent data, not its own.

  • NULL is a null pointer constant.
IF F_Gate(saveRequested) THEN
  SaveSettings();
END_IF

Which version is running

libraryVersion := F_GetVersion();

16Messages and what to do

Turn the log on first (section 2, step 5). Messages go to the TwinCAT log, which shows in XAE's Error List and output window. Messages from a block that extends T_NamedBase start with its instance path, for example:
